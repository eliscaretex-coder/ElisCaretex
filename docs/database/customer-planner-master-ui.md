# Customer Planner and Customer Master UI

## Navigation

The Customer module is separated into:

1. Schedule Planner;
2. Customer Master;
3. Distribution, when authorized.

This avoids mixing schedule visibility with Customer Master maintenance.

## Schedule Planner

The planner follows the established weekly matrix:

- days across the page;
- customer order beside the name;
- trolley summary beside the customer;
- Clothes and MOP lists are separate;
- horizontal scrolling is limited to the planner;
- clicking a customer opens all production days.

No schedule row is edited directly in this interface.

## Customer Master

The master list uses the controlled database functions:

- `create_customer_master()`;
- `update_customer()`;
- `deactivate_customer()`;
- `reactivate_customer()`.

A technical customer code is generated by PostgreSQL when a customer is added.

## Deactivation

The interface uses the word `Deactivate`, even where the user thinks of the
action as delete.

Deactivation:

- removes the customer from operational planners;
- closes active services;
- supersedes the published schedule;
- preserves all historical records and audit information.

## Permissions

- ADMIN, MANAGER and PLANNER may create and update Customer Master records.
- ADMIN and MANAGER may deactivate or reactivate customers.
- Distribution fields are loaded only in Customer Master maintenance or the
  Distribution view.
- Operational area users receive only their permitted schedule.
